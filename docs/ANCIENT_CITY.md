# Ancient Threshold — 1.8 gateway and worldgen notes

## Source of the dimensions

The implementation was checked against **all three vanilla Minecraft 1.21.1 city-center templates**, not another mod’s portal implementation:

- [city_center_1.nbt](https://github.com/misode/mcmeta/blob/1.21.1-data/data/minecraft/structure/ancient_city/city_center/city_center_1.nbt)
- [city_center_2.nbt](https://github.com/misode/mcmeta/blob/1.21.1-data/data/minecraft/structure/ancient_city/city_center/city_center_2.nbt)
- [city_center_3.nbt](https://github.com/misode/mcmeta/blob/1.21.1-data/data/minecraft/structure/ancient_city/city_center/city_center_3.nbt)

Each template is 18×31×41. The frame occupies local **x=13, y=17..24, z=10..31**: 22×8 outside, 20×6 inside. The raw files contain 55 reinforced blocks plus a jigsaw at **(13,24,20)** whose `final_state` is `minecraft:reinforced_deepslate`. Natural generation therefore yields the complete **56-block outline**. Missing aperture cells in the raw template are not an instruction to delete terrain; this mod refuses to open an obstructed aperture.

## Activation and compatibility

- One Echo Shard in the interacting hand; right-click any outline block.
- Survival: Overworld, within an Ancient City structure piece, complete outline, clear aperture, all inspected chunks loaded, vanilla modification permission for every changed block.
- Creative: matching replicas in other locations work; no shard consumption.
- Both X/Y and Z/Y planes work, including all vanilla city rotations.
- No destructive clearing, no catalyst requirement, no unnecessary chunk generation during shape detection. The bounded matcher caches its block reads.
- Fully open gateways consume nothing. Partially open, otherwise intact gateways can be completed for one shard.
- Frame integrity is checked on activation, **not continuously afterward**. Removing a frame block does not automatically dismantle an already-active membrane. This intentionally preserves old active gates.
- Third-party claim/protection integration beyond vanilla modification permission is not implemented.
- Existing active 4×5 gates and sanctuary return blocks remain functional. No new 4×5 gates or reinforced-deepslate crafting recipe.
- Return searches are bounded to loaded nearby blocks after loading the recorded return chunk. A blocked landing fails without losing the saved return point. This checks geometry and fluids, not nearby enemies.

## Terrain and presentation

`generate_realm_data.py` owns the new broad basin noise, folded-ridge density, vertical-bounded ravine mask, cave composition, surface stone band, biome ambience, and scenery placement. `RealmScenery` supplies low-scale, biome-specific decoration between larger structures. Fen ponds require flat natural ground and an intact rim; all decoration writes stay in the owning chunk. The central sanctuary/arena approach remains reserved.

The Hollow Keep remains a deliberately authored fortress in its own void dimension, not a second copy of wilderness terrain. New fortresses receive integrated hall and ward lighting. Existing built fortresses are left untouched to avoid overwriting player changes.

Existing terrain is never regenerated by this update. **Use a fresh test world or explore new chunks.** Terrain seams at old/new boundaries are expected; no custom blending or old-chunk migration is provided.

## Validation boundaries

JUnit exercises every outline click in both planes, all 120 aperture obstructions, every missing outline block, partial/already-open interiors, and rejection of legacy-small shapes. The dedicated-server smoke places all three actual vanilla templates in four rotations, finalizes the top jigsaw as vanilla generation does, and opens them through the same shape matcher and membrane builder used by player activation. It separately checks blocked interiors. This verifies template compatibility and actual server block states, **not** a player's hand interaction or teleport round trip.

Manual checks still required: naturally generated-city activation in Survival; main/offhand consumption; protected locations; connected-player entry/return/restart; obstructed returns; animated portal rendering; screenshots across seeds and region boundaries; scenery appearance and traversal; old-save migration; multiplayer timing and balance.

## Documentation pictures

`python3 scripts/generate_gallery.py` regenerates the README plates with Python’s standard library:

- Item gallery: actual local item PNGs, embedded and enlarged.
- Creature gallery: cuboids and hierarchical pivots parsed from the current Java models; simplified material colors, not in-game rendering.
- Biome plates: actual local block textures, not terrain screenshots.
- Portal route: hand-designed schematic drawn to the researched frame proportions.

The generator fails on unsupported construction loops/expressions instead of silently guessing geometry. Live animation, UV mapping, emissive passes, renderer scale, and gameplay screenshots are outside its scope.
